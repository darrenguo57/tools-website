Number Base Conversion: Binary, Hex, Octal Explained

Number bases are foundational to programming. Computers operate in binary, programmers think in hexadecimal, and Unix file permissions use octal. Understanding how these number systems relate to each other helps you read memory dumps, debug bitwise operations, write CSS color codes, and set file permissions correctly. This guide explains each base, how to convert between them, and where each one appears in real development work.

Understanding Number Bases

A number base, or radix, is the number of unique digits used to represent numbers. The base-10 (decimal) system we use every day has ten digits: 0 through 9. In positional notation, each digit's position determines its weight as a power of the base. The number 347 in base 10 means 3 x 10^2 + 4 x 10^1 + 7 x 10^0 = 300 + 40 + 7.

Computers use binary (base 2) because their fundamental hardware component, the transistor, has two states: on and off, represented as 1 and 0. Every piece of data in a computer, from text to images to executable code, is ultimately stored as sequences of binary digits (bits). A group of eight bits is called a byte, which can represent 256 distinct values (2^8).

The challenge with binary for humans is that even small numbers produce long, hard-to-read strings. The decimal number 255 is 11111111 in binary. To bridge the gap between human-readable and machine-native representations, hexadecimal (base 16) and octal (base 8) serve as compact shorthand for binary values.

Binary (Base 2) Deep Dive

Binary uses two digits, 0 and 1. Each position represents a power of 2. The binary number 1010 equals 1 x 2^3 + 0 x 2^2 + 1 x 2^1 + 0 x 2^0 = 8 + 0 + 2 + 0 = 10 in decimal. Reading binary is about recognizing the positional values: from right to left, they are 1, 2, 4, 8, 16, 32, 64, 128, and so on, doubling each time.

A byte, which is 8 bits, can represent values from 0 (00000000) to 255 (11111111). When dealing with signed integers, the most significant bit (leftmost) is the sign bit: 0 for positive, 1 for negative. The most common signed representation is two's complement, where -1 in 8-bit is 11111111, and the range becomes -128 to 127.

Bitwise operations act directly on binary representations. The AND operator (&) returns 1 only when both bits are 1. The OR operator (|) returns 1 when either bit is 1. The XOR operator (^) returns 1 when bits differ. The left shift (<<) moves all bits left by a given number of positions, effectively multiplying by 2 for each position shifted.

Hexadecimal (Base 16) Deep Dive

Hexadecimal uses sixteen digits: 0-9 and A-F, where A=10, B=11, C=12, D=13, E=14, and F=15. The reason hex is so prevalent in programming is that one hex digit maps exactly to four bits (a nibble). Two hex digits map to one byte. This makes hex the most compact human-readable representation of binary data: a 32-bit memory address is 8 hex digits instead of 32 binary digits.

In CSS, colors are expressed in hex. The color #FF5733 represents red=255, green=87, blue=51. Each pair of hex digits is one byte (0-255). The 0x prefix is used in many programming languages to denote hexadecimal literals: 0xFF equals 255 in decimal.

Converting hex to decimal:
0xFF5733
= F x 16^5 + F x 16^4 + 5 x 16^3 + 7 x 16^2 + 3 x 16^1 + 3 x 16^0
= 15 x 1048576 + 15 x 65536 + 5 x 4096 + 7 x 256 + 3 x 16 + 3
= 15728640 + 983040 + 20480 + 1792 + 48 + 3
= 16733999

Hex appears in memory addresses during debugging (e.g., 0x7ffee3b8c000), MAC addresses (e.g., 00:1A:2B:3C:4D:5E), IPv6 addresses, hash digests (SHA-256 outputs are 64 hex characters), and Unicode code points (U+0041 for the letter A). When you see hex in code, it usually means the value is a bitmask, a memory address, or a raw byte value.

Octal (Base 8) and Its Uses

Octal uses digits 0-7. Each octal digit maps to exactly three bits, which made it natural on systems with 12-bit, 24-bit, or 36-bit word sizes. While less common today than hex, octal still appears in specific contexts. The most prominent is Unix file permissions, where the chmod command takes an octal number representing read (4), write (2), and execute (1) bits for the owner, group, and others.

For example, chmod 755 file sets permissions to rwxr-xr-x: owner has 7 (4+2+1 = full access), group has 5 (4+1 = read and execute), and others have 5 (read and execute). JavaScript supports octal literals with the 0o prefix: 0o755 equals 493 in decimal. The older 0-prefix syntax (0755) is deprecated and forbidden in strict mode because it caused bugs when developers intended a leading zero to be cosmetic.

In some languages like C and Java, a leading zero on an integer literal still denotes octal, which has caused bugs where developers used leading zeros for alignment and accidentally changed the value. Modern style guides recommend against leading zeros for this reason.

Converting Between Bases

The division-remainder method converts from decimal to any base. To convert a decimal number to base B, repeatedly divide by B and collect the remainders in reverse order. For example, converting 255 to hex: 255 / 16 = 15 remainder 15 (F), 15 / 16 = 0 remainder 15 (F). Reading the remainders bottom-up gives FF.

Converting between binary and hex is simpler. Group the binary digits into groups of four (from right to left), then map each group to its hex digit. The binary 11111111 groups as 1111 1111, and each 1111 is F, giving FF. This direct mapping is why hex is preferred over octal on modern byte-oriented systems: 4 bits per hex digit divides evenly into 8-bit bytes, while 3 bits per octal digit does not.

// JavaScript: built-in conversion methods
const num = 255;

console.log(num.toString(2));   // "11111111" (binary)
console.log(num.toString(8));   // "377" (octal)
console.log(num.toString(16));  // "ff" (hex)

// Parsing strings in specific bases
console.log(parseInt("FF", 16));  // 255
console.log(parseInt("11111111", 2)); // 255
console.log(parseInt("377", 8));  // 255

// Python
print(bin(255))   # 0b11111111
print(hex(255))   # 0xff
print(oct(255))   # 0o377
print(int("FF", 16))  # 255

Most programming languages provide built-in functions for base conversion. JavaScript's Number.toString(radix) and parseInt(string, radix) handle conversion from any base to any base (through decimal as an intermediate). Python's bin(), hex(), and oct() produce prefixed string representations, while int(string, base) parses any base.

Practical Applications

Bitmask flags are a common application of number bases. A single integer can represent multiple boolean flags, each occupying one bit. For example, Unix file permissions pack read (4), write (2), and execute (1) into one digit per entity. A value of 0o755 uses three octal digits to encode nine permission bits in a compact form.

Color manipulation in CSS and canvas APIs uses hex. When you need to extract the red component from #FF5733, you mask the first byte and shift: in JavaScript, (0xFF5733 >> 16) & 0xFF gives 255, the red value. Similar bit operations extract green and blue. Understanding these operations requires comfort with hex and binary.

Low-level debugging involves reading memory dumps and network packet captures displayed in hex. Tools like xxd and Wireshark show data in hex with ASCII annotations. Recognizing patterns in hex output, such as ASCII character ranges (41-5A for uppercase letters) or common markers (0x89504E47 for PNG headers), speeds up debugging significantly.

Working with Binary Data in Code

When programming, you frequently need to represent binary data as text for display, logging, or transport. Hex encoding doubles the data size (each byte becomes two hex characters) but is self-evident and easy to read. Base64 is more compact (33% larger) but uses characters that require a lookup table to decode. The choice between them depends on whether the data needs to be human-readable or compact.

In network programming, binary protocols often use hex for documentation and debugging. The HTTP/2 frame format, the WebSocket handshake, and TCP segment headers are all documented in hex. When you capture a packet with Wireshark, the default display is hex with ASCII annotation, allowing you to see both the raw bytes and any printable characters they contain. Understanding hex lets you read these captures directly without needing to convert.

// Bitwise operations for flags
const READ = 0b100;  // 4
const WRITE = 0b010; // 2
const EXEC = 0b001;   // 1

// Combine flags with OR
const perms = READ | WRITE;  // 0b110 = 6

// Check a flag with AND
const canWrite = (perms & WRITE) !== 0; // true

// Toggle a flag with XOR
const toggled = perms ^ EXEC; // 0b111 = 7

Bit manipulation with flags is a practical application where understanding binary is essential. Each flag occupies one bit, and combining them with OR produces a single integer that encodes multiple boolean values. This pattern is used in file permissions, graphics rendering state, capability flags in APIs, and protocol headers. Reading 0b110 and knowing it means "read and write but not execute" requires comfort with binary representation.

When debugging numeric issues, converting between bases helps identify problems. If a calculation produces an unexpected result, viewing the number in binary can reveal overflow (bits beyond the representable range), sign extension issues (the sign bit propagating incorrectly), or truncation (losing upper bits). JavaScript's bitwise operators work on 32-bit signed integers, which means numbers above 2^31 behave unexpectedly in bitwise contexts. Knowing this limitation prevents subtle bugs.

Frequently Asked Questions

Why do programmers use hexadecimal?

Hex provides a compact, human-readable representation of binary data. Each hex digit represents exactly four bits, so a byte is always two hex digits. This makes hex the natural shorthand for memory addresses, color values, hash digests, and raw byte data in debugging.

How do I convert binary to hex quickly?

Group the binary digits into groups of four, starting from the right. Pad the leftmost group with zeros if needed. Then map each group to its hex digit (0000=0, ..., 1001=9, 1010=A, ..., 1111=F). This works because 16 is a power of 2, so the grouping aligns perfectly.

What is the difference between Base64 and hex?

Hex encoding uses 16 characters and produces output that is twice the size of the binary input. Base64 uses 64 characters and produces output that is about 33% larger than the input. Base64 is more space-efficient; hex is more human-readable and easier to type. Both are reversible and provide no security.

Why does JavaScript use 0x for hex?

The 0x prefix comes from C and was adopted by JavaScript and many other languages. The 0 tells the parser this is a numeric literal, and the x specifies hexadecimal. Similarly, 0b denotes binary and 0o denotes octal in modern JavaScript.

What's the largest number in 8-bit binary?

The largest unsigned 8-bit number is 255 (11111111 in binary, 0xFF in hex). For signed integers using two's complement, the range is -128 to 127, so the largest positive value is 127 (01111111).
