QR Codes and Barcodes: Generation and Use Cases

QR codes and barcodes encode machine-readable data into visual patterns. QR codes store two-dimensional data in a square grid, while linear barcodes store one-dimensional data in parallel lines. This guide explains the technology behind each, walks through generation with code, and covers the practical use cases, from contactless payments to warehouse inventory.

QR Code Technology Explained

A QR (Quick Response) code is a two-dimensional barcode invented by Denso Wave in 1994 for tracking automotive parts. Unlike a linear barcode, which encodes data in one direction, a QR code encodes data in both dimensions of a square grid of black and white modules. This gives it far higher data capacity: a QR code can hold up to 7,089 numeric characters or 2,953 bytes of binary data, compared to a Code-128 barcode's maximum of about 80 characters.

The structure of a QR code includes finder patterns (the three large squares in the corners that let a scanner locate and orient the code), timing patterns (alternating modules that help the scanner determine the grid size), format information (error correction level and mask pattern), data and error correction codewords, and a quiet zone (a mandatory margin of white space around the code). The finder patterns make QR codes readable at any rotation and from any direction.

Error correction is a key feature. QR codes use Reed-Solomon error correction, which adds redundant data so the code remains scannable even when partially damaged or obscured. There are four levels: L (7% recovery), M (15% recovery), Q (25% recovery), and H (30% recovery). Higher error correction lets you add logos or decorations over part of the code, at the cost of reduced data capacity.

LevelRecoveryUse Case
L (Low)~7%Maximum data, clean environment
M (Medium)~15%Standard, balanced (default)
Q (Quartile)~25%Outdoor, some branding overlay
H (High)~30%Industrial, logo overlay, dirty surfaces

The version number of a QR code, from 1 to 40, determines its module grid size and data capacity. Version 1 is a 21x21 grid holding up to 25 alphanumeric characters; version 40 is a 177x177 grid holding up to 4,296 alphanumeric characters at error correction level L. Most QR codes in the wild are versions 2 through 7, balancing capacity and scannability. Higher versions pack more data but require larger physical size to remain scannable, because each module must be wide enough for the camera sensor to resolve. This is why QR codes on business cards, which need only encode a short URL, are small, while codes encoding a full vCard are noticeably larger.

QR Code Use Cases

QR codes bridge physical and digital worlds. The most common use case is URL sharing: a code printed on a poster, packaging, or business card opens a website when scanned. This eliminates the need to type URLs, which is error-prone on mobile keyboards. Restaurant menus, event registrations, and product information pages all use QR codes for instant access.

WiFi sharing encodes network credentials so guests can join by scanning instead of typing a complex password. The format is WIFI:T:WPA;S:NetworkName;P:Password;;. Contact cards (vCard) encode name, phone, email, and address so scanning adds the contact directly to the phone's address book. Payments use QR codes to encode payment URLs or account identifiers, enabling contactless transactions without NFC hardware.

// QR code content formats for different use cases

// 1. URL (most common)
const urlContent = 'https://useeasytool.com/tools/generators/qrcode.html';

// 2. WiFi credentials
const wifiContent = 'WIFI:T:WPA;S:MyNetwork;P:MySecurePassword123;H:false;;';
// T: security type (WPA/WEP/nopass), S: SSID, P: password, H: hidden network

// 3. vCard (contact card)
const vcardContent = `BEGIN:VCARD
VERSION:3.0
FN:UseEasyTool Team
ORG:UseEasyTool
TEL:+1-555-0100
EMAIL:contact@useeasytool.com
URL:https://useeasytool.com
END:VCARD`;

// 4. Email with pre-filled subject and body
const emailContent = 'mailto:contact@useeasytool.com?subject=Support%20Request&body=Describe%20your%20issue';

// 5. SMS
const smsContent = 'SMSTO:+15550100:Hello, I have a question';

// 6. Geolocation
const geoContent = 'geo:37.7749,-122.4194';  // San Francisco coordinates

// 7. Plain text
const textContent = 'Event code: EVT-2024-8847';

For inventory management, QR codes encode product IDs, serial numbers, or batch numbers that scanners read at receiving, storage, and shipping points. Each scan updates the inventory system in real time, eliminating manual data entry errors. The two-dimensional capacity lets a single code hold enough data to identify a product without a database lookup, useful when scanners are offline.

Barcode Types and Standards

Linear barcodes encode data in the widths of parallel bars and spaces. Code-128 is the most versatile, supporting all 128 ASCII characters with high density. It is used in shipping labels, packaging, and logistics. EAN-13 (European Article Number) is the 13-digit barcode on retail products worldwide; the first digits identify the country or GS1 prefix, the next identify the manufacturer and product, and the last is a check digit.

UPC-A is the 12-digit North American equivalent of EAN-13, used on retail products in the US and Canada. ISBN barcodes on books are EAN-13 codes derived from the ISBN, starting with the GS1 prefix 978 or 979. Code-39 is an older format that encodes 43 characters (A-Z, 0-9, and seven symbols) and is still common in automotive and defense.

// Barcode selection guide
/*
  Code-128   — Shipping, logistics, packaging (full ASCII, high density)
  EAN-13     — Retail products worldwide (13 digits, fixed format)
  UPC-A      — Retail products in US/Canada (12 digits)
  EAN-8      — Small retail items where EAN-13 won't fit (8 digits)
  Code-39    — Industrial, automotive (alphanumeric, low density)
  ITF-14     — Cartons and outer packaging (14 digits, numeric only)
  ISBN       — Books (EAN-13 with 978/979 prefix)
  DataMatrix — 2D, small items, pharma (compact, high capacity)

  Check digit calculation for EAN-13:
  Multiply alternate digits by 1 and 3, sum, round up to nearest 10
*/
function ean13CheckDigit(twelveDigits) {
  const digits = twelveDigits.split('').map(Number);
  let sum = 0;
  for (let i = 0; i < 12; i++) {
    sum += digits[i] * (i % 2 === 0 ? 1 : 3);
  }
  return (10 - (sum % 10)) % 10;
}

console.log(ean13CheckDigit('400638133393'));  // Output: 1
// Full EAN-13: 4006381333931

Generating QR Codes

QR code generation in JavaScript is straightforward with libraries like qrcode. The key parameters are the data to encode, the error correction level, and the size. Most libraries render to canvas, SVG, or a data URL for embedding in HTML. Choose the error correction level based on the environment: M for clean digital display, H for print or outdoor use where damage is likely.

// QR code generation with the qrcode npm package
import QRCode from 'qrcode';

// Generate as data URL (for )
const dataUrl = await QRCode.toDataURL('https://useeasytool.com', {
  errorCorrectionLevel: 'M',  // L, M, Q, H
  width: 300,                  // Pixel size
  margin: 2,                   // Quiet zone in modules (min 4 recommended)
  color: {
    dark: '#000000',           // Module color
    light: '#FFFFFF'           // Background color
  }
});

// Render to canvas
const canvas = document.getElementById('qr-canvas');
await QRCode.toCanvas(canvas, 'https://useeasytool.com', {
  errorCorrectionLevel: 'H',
  width: 256,
  margin: 4
});

// Render as SVG (scales without pixelation)
const svgString = await QRCode.toString('https://useeasytool.com', {
  type: 'svg',
  errorCorrectionLevel: 'M',
  margin: 2
});

// Dynamic QR with high error correction for branding overlay
const brandedQR = await QRCode.toDataURL(wifiContent, {
  errorCorrectionLevel: 'H',  // 30% recovery — allows logo overlay
  width: 400,
  margin: 4,
  color: { dark: '#1a1a2e', light: '#FFFFFF' }
});
// A logo can cover up to 30% of the code without breaking it

Size matters for scannability. The minimum recommended physical size is calculated as (module count + 8 * quiet zone) * print density. A version 3 QR code (29x29 modules) with the minimum quiet zone of 4 modules per side needs at least 37 modules. At 4 pixels per module (typical for screen display), that is 148 pixels. For print at 300 DPI, a 1-inch QR code is 300 pixels, giving about 8 pixels per module, which scans reliably.

QR Code Design Best Practices

Several design decisions affect whether a QR code scans reliably. Contrast is critical: dark modules on a light background works best. Avoid low-contrast color schemes like yellow on white or dark blue on black. While you can use custom colors, the difference in luminance between dark and light must be sufficient; test with a grayscale conversion to verify.

The quiet zone (the white border around the code) must be at least 4 modules wide. Without it, scanners cannot distinguish the code from surrounding content. Placement should be flat, well-lit, and unobstructed. Curved surfaces, glare from lamination, and reflective materials can prevent scanning. Always test with real devices under real conditions before mass production.

// QR code validation checklist before deployment
function validateQRConfig(config) {
  const warnings = [];

  // Size check: minimum 2x2cm at print resolution
  if (config.width < 150) {
    warnings.push('Warning: QR code smaller than 150px may not scan reliably on print');
  }

  // Quiet zone check
  if (config.margin < 4) {
    warnings.push('Warning: Quiet zone below 4 modules — scanners may fail');
  }

  // Contrast check
  const darkLum = luminance(config.color.dark);
  const lightLum = luminance(config.color.light);
  const contrast = (Math.max(darkLum, lightLum) + 0.05) /
                   (Math.min(darkLum, lightLum) + 0.05);
  if (contrast < 4.5) {
    warnings.push(`Warning: Contrast ratio ${contrast.toFixed(1)}:1 below recommended 4.5:1`);
  }

  // Data size check — large data increases version and reduces scan reliability
  if (config.data.length > 200 && config.errorCorrectionLevel === 'H') {
    warnings.push('Warning: Large data + high error correction creates a dense code');
  }

  return warnings;
}

function luminance(hex) {
  const r = parseInt(hex.slice(1, 3), 16) / 255;
  const g = parseInt(hex.slice(3, 5), 16) / 255;
  const b = parseInt(hex.slice(5, 7), 16) / 255;
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

If you add a logo to the center of a QR code, use error correction level H and keep the logo under 30% of the total code area. The logo must not obscure finder patterns (the three corner squares) or timing patterns. Test the final branded code on multiple devices, because decorative effects that look good in design tools can break scanning.

Security Considerations

QR codes are opaque to users: a code looks the same whether it links to a legitimate website or a phishing page. This has given rise to quishing (QR phishing), where malicious QR codes in emails or public spaces direct users to credential-harvesting sites. Because users cannot read a QR code by eye, they scan it blindly, trusting the destination.

Mitigation requires both user education and technical safeguards. On the user side, recommend QR scanners that preview the URL before opening it, so the user can verify the destination. On the implementation side, if you generate QR codes for your application, use signed URLs that include a verification token, so the server can detect tampering. For WiFi QR codes, be aware that the credentials are stored in plaintext in the code; anyone who photographs the code has the network password.

// Signed URL QR code to prevent tampering
import crypto from 'crypto';

function generateSignedURL(baseUrl, secret) {
  const expiry = Math.floor(Date.now() / 1000) + 3600;  // 1 hour expiry
  const payload = `${baseUrl}?expires=${expiry}`;

  // HMAC signature
  const signature = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('base64url');

  const signedURL = `${payload}&sig=${signature}`;
  return signedURL;
}

// Server-side verification
function verifySignedURL(url, secret) {
  const urlObj = new URL(url);
  const expires = parseInt(urlObj.searchParams.get('expires'));
  const providedSig = urlObj.searchParams.get('sig');

  // Check expiry
  if (Date.now() / 1000 > expires) {
    return { valid: false, reason: 'URL expired' };
  }

  // Reconstruct and verify signature
  const payload = `${urlObj.origin}${urlObj.pathname}?expires=${expires}`;
  const expectedSig = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('base64url');

  if (!crypto.timingSafeEqual(
    Buffer.from(providedSig),
    Buffer.from(expectedSig)
  )) {
    return { valid: false, reason: 'Invalid signature' };
  }

  return { valid: true };
}

For public-facing QR codes, consider using short URLs that redirect through your own domain, which lets you change the destination later without reprinting the code and lets you track scan analytics. Always use HTTPS for QR destinations, because HTTP URLs are flagged as insecure by modern mobile browsers and some scanners refuse to open them.

Frequently Asked Questions

What is error correction in QR codes?

Error correction uses Reed-Solomon coding to add redundant data so a QR code remains scannable even when partially damaged. The four levels, L, M, Q, and H, recover approximately 7%, 15%, 25%, and 30% of data respectively. Higher levels allow logo overlays but reduce data capacity.

How much data can a QR code hold?

A QR code can hold up to 7,089 numeric characters, 4,296 alphanumeric characters, 2,953 bytes of binary data, or 1,817 kanji characters. Actual capacity depends on the error correction level and the data type, with higher error correction reducing capacity.

What's the difference between QR codes and barcodes?

Linear barcodes encode data in one dimension as parallel lines of varying widths, holding about 20-80 characters. QR codes encode data in two dimensions as a grid of modules, holding thousands of characters. QR codes also include built-in error correction and can be read at any angle.

Can QR codes be customized?

Yes, within limits. You can change the module and background colors, add a logo to the center (using error correction level H, keeping the logo under 30% of the area), and use rounded modules. Always test custom designs with multiple devices, as heavy customization can break scanning.

How small can a QR code be?

The minimum scannable size depends on the module count and print resolution. As a rule, each module should be at least 0.4mm (about 4 pixels at 300 DPI). A small version 1 QR code (21x21 modules) with quiet zone needs about 1.2cm at 300 DPI. Smaller codes may scan unreliably.
