How to Use

About This Tool

The URL Signature tool generates and verifies signed URLs using HMAC-SHA256. Signed URLs are commonly used to grant temporary access to private resources, validate callback URLs, and prevent URL tampering. By appending a signature parameter, the recipient can verify that the URL was generated by someone who possesses the shared secret.

Input Guide

Enter the base URL and any query parameters. Provide a secret key used for signing. Set an expiration timestamp if you want the link to be time-limited. The tool sorts parameters alphabetically before signing to ensure consistent signatures. When verifying, paste the full signed URL and enter the same secret; the tool will confirm whether the signature is valid and whether the link has expired.

Output

The signing output is a complete URL with a signature parameter appended. For time-limited links, an expires parameter is also included. The verification output indicates whether the signature matches, which parameters were checked, and if the expiration time has passed. Invalid or expired URLs are flagged with a clear error message.

Tips & Notes

  • Always use HTTPS when transmitting signed URLs to prevent man-in-the-middle attacks.
  • Keep the secret key on the server; never expose it in client-side code.
  • Parameter order does not matter because the tool sorts them before signing.
  • Short expiration times reduce the window of opportunity for replay attacks.

Common Use Cases

Cloud storage providers generate temporary download links for private files. E-commerce platforms create signed redirect URLs for affiliate tracking. SaaS applications verify webhook callbacks to ensure they originated from a trusted partner. Content platforms protect hotlinked media by requiring valid signatures in the request URL.
