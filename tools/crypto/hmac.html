How to Use

About This Tool

The HMAC Generator creates Hash-based Message Authentication Codes using SHA-256, SHA-512, and other hash functions. HMAC combines a secret key with a hash function to produce a signature that verifies both the integrity and authenticity of a message. It is widely used in API authentication, webhook verification, and JWT token signing.

Input Guide

Enter the message you want to sign and provide a secret key. The key can be any ASCII or UTF-8 string. Select the hash algorithm; SHA-256 is the most common choice for APIs. If you are verifying a signature, paste the original message, enter the same key, and compare the generated HMAC with the one you received. Even a single character change in either the message or key will produce a completely different HMAC.

Output

The output is a hexadecimal string representing the HMAC digest. A Base64-encoded variant is also available. The output length matches the chosen hash function: 64 hex characters for SHA-256 and 128 for SHA-512. There is no practical way to reverse an HMAC without brute-forcing the secret key.

Tips & Notes

  • Keep your secret key confidential; anyone with the key can forge valid signatures.
  • Use a cryptographically random key with at least the same length as the hash output.
  • HMAC-SHA256 is preferred over HMAC-MD5 for all new implementations.
  • When comparing HMACs, use a constant-time comparison to prevent timing attacks.

Common Use Cases

Backend developers verify webhook signatures from payment providers like Stripe or PayPal. API architects implement request signing for stateless authentication. Mobile developers sign local data to detect tampering. DevOps engineers validate integrity of deployment artifacts using shared secrets.
